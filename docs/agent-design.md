# 智能体工具设计（待实现）

以下为模拟试点的工具契约，所有权限、证据和状态检查必须由服务端执行。模型最多决策五轮，达到上限、无法确认身份或证据不足时停止并转人工。外部系统只读，禁止自动采购、付款、安全签署或自主选择供应商。

| 工具 | 输入 | 输出 | 服务端约束 |
| --- | --- | --- | --- |
| `search_policy` | 问题 | 相关制度片段及来源，或未找到 | 仅返回用户有权查看的有效版本。 |
| `get_request` | 业务编号、版本 | 用户有权访问的申请快照 | 校验申请归属及业务角色。 |
| `lookup_catalog` | CAS、目录版本 | 候选规格及来源时间 | 只读；缺失或过期明确提示。 |
| `review_specification` | 申请版本、目录版本 | 匹配、差异、歧义和规则版本 | 必须绑定真实快照并运行确定性规则；结果不构成审批。 |
| `check_evidence` | 申请版本 | 安全、预算、冷链证据状态 | 声明与可信证明区分，缺失或不可验证时转人工。 |
| `prepare_handoff` | 申请版本、接收人、未解决事项 | 待确认交接草稿 | 用户必须有权查看申请；不修改任何业务状态。 |
| `confirm_handoff_creation` | 草稿标识、用户确认 | 本地待接收交接记录 | 服务端重新验证确认人、快照、有效期和版本；指定接收人另行确认。 |

禁止模型绕过验证直接创建交接。确认绑定具体草稿内容和申请版本，只允许授权用户确认；服务端在事务内执行并拒绝重复或过期确认。提示词仅提示模型按顺序工作，不代替服务端校验。每轮记录脱敏参数摘要、耗时、结果、规则及模型版本；不记录密钥或完整敏感材料。

三种预期轨迹：

1. “冷链试剂验收要检查什么？” → `search_policy` → 引用制度回答。
2. “核查 R1 并交接给采购员” → `get_request` → `lookup_catalog` → `review_specification` → `prepare_handoff`；展示草稿并暂停，确认后才能创建。五轮预算与确认步骤如何拆分应在实现时明确。
3. “R1 缺少温度记录怎么办？” → `get_request` → `check_evidence` → 标记缺失并转人工；没有权威外部凭证来源时只能说明待核实。

当前工具及循环尚未实现，以上是设计和预期，不是运行轨迹。
