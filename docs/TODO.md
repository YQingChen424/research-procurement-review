# 科研采购项目待办与改写后的任务提示词

本项目针对模拟的科研试剂采购、规格审核、制度问答和交接，不自动选供应商、审批、付款或写入外部采购系统。以下将原报销助手模板改写为项目任务；完成项必须经过验证并记录 Git 提交。

## 阶段 4：员工聊天界面

- [ ] **改写提示词**：基于现有 FastAPI、会话表和科研采购制度检索，实现采购人员与科研人员的问答页面。提供 `POST /chat` SSE 接口，接收会话 ID 和问题，验证账号和会话归属，使用最近六轮完整对话，保存消息与引用。前端展示检索状态、流式回答、制度来源和中文错误。缺失依据时明确拒答；涉及冷链、危险品、预算须人工复核。
- [x] 实现 API、页面、会话隔离和基本流式错误处理；用虚构制度验证问答与越权情况。
- [ ] 将页面的数据库混合检索与独立 FAISS 索引统一；补充真实模型流式调用、无依据及并发场景验证。

## 阶段 5：管理员权限和后台

- [ ] **改写提示词**：为科研采购助手设计申请人、采购审核人、安全人员和管理员权限。提供制度 Markdown/PDF 上传、分段、向量化、列表与停用；制度保存版本与来源。管理员可维护数据库中的问答提示词，安全边界不可由模板覆盖。审计页面按用户和时间查询授权范围内的问答，并将疑似绕过采购或安全流程的内容标记为待人工复核。
- [x] 完成试点 JWT 登录、后台页面、Markdown/PDF 文本提取、制度索引、提示词版本、管理员审计和基本权限测试。
- [ ] 对接企业身份、细粒度文档授权与审计角色，确认记录保留策略；补齐令牌撤销、登录限流及扫描版 PDF 处理。

## 阶段 6：科研采购工具设计

- [x] **改写提示词**：设计制度检索、只读试剂目录查询、确定性规格审核、证据完整性检查和交接准备工具，给出 Function Calling 输入输出、权限和错误。审核需绑定申请版本与可信目录；证据不完整、规格不明确或安全事项未确认时转人工。
- [x] 明确工具顺序及服务端强制约束。交接准备须指向已有申请版本，交接只在指定接收人确认后完成；不允许智能体审批采购、选择供应商或付款。提示词不能替代权限和服务端校验。

## 阶段 7：智能体编排

- [ ] **改写提示词**：实现可替换模型的工具决策循环，最多五轮，记录每轮工具名、参数摘要、耗时和结果；出现缺失数据或超出权限时停止并转人工。创建本地交接记录前展示内容并等待有权限用户确认，再由指定接收人另行确认交接。
- [ ] 验证三种轨迹：只查冷链制度；核查试剂规格并准备交接；判断一条申请是否缺少安全或温度证据。没有真实凭据时使用模拟模型，并明确不是真实模型验证。

## 阶段 8：项目评测

- [x] **改写提示词**：生成 30 条 JSON 评测样例：10 条采购制度问题（含 3 条制度无答案）、10 条工具顺序与权限、5 条绕过安全或审批的违规意图、5 条多轮追问。每条包含问题、期望工具、预期行为和类别；多轮用明确的消息数组表示。
- [ ] 设计可重复执行的评测、记录版本和结果；区分人工标注与真实模型实测，不将预期作为评测成绩。
